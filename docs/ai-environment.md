# AI-окружение: установка и восстановление

Этот публичный dotfiles-репозиторий хранит состав окружения, установщики,
безопасные шаблоны и правила. Рабочие конфиги Codex, Claude Code и OpenCode
генерируются локально и не публикуются. Главный список версий и компонентов:
[environment.json](../.config/dotfiles-ai/environment.json).

## Что должно быть установлено

| Компонент | Назначение | Где нужен |
|---|---|---|
| Codex, Claude Code, OpenCode | Клиенты; установить и авторизовать отдельно | Все три |
| Git, GitHub CLI (`gh`) | Репозитории и локальная авторизация GitHub MCP | Все три |
| Python 3.11+, Node.js 18+, npm/npx | Установщик и запуск MCP | Все три |
| Codebase Memory MCP | Граф структуры кода и проверка покрытия | Все три |
| Context7 MCP | Актуальная документация публичных библиотек/API | Все три |
| Официальный GitHub MCP | Работа с GitHub, issues, PR и Actions | Все три |
| Playwright MCP + Chromium/Chrome | Проверка пользовательских веб-сценариев | Все три |
| Matt Pocock skills | Планирование, диагностика, TDD, ревью, передача работы | Все три |

`uv/uvx` нужны для дополнительных Python MCP. `code-index-mcp`, `filesystem`,
`memory`, `sequential-thinking`, `tree-sitter` и macOS Homebrew MCP — дополнительные
существующие подключения. Установщик их сохраняет, но не добавляет всем заново.
Встроенные чтение файлов и терминал клиентов остаются доступны без этих MCP.
MCP графа Codebase Memory и проект Graph (ныне `pvs-efs-assist`) — разные вещи.

Срез проверенных версий: GitHub MCP 2.1.0, Playwright MCP 0.0.85,
Matt Pocock plugin 1.3.2, OpenCode на второй машине 2.3.0. Версии серверов и
точный commit копий навыков OpenCode зафиксированы в манифесте. Плагины
Codex/Claude устанавливаются штатными менеджерами из репозитория автора;
их последующее обновление и версия проверяются отдельно, они не привязаны
к commit OpenCode. Первую машину и macOS ещё нужно проверить на месте.

## Восстановление на компьютере

1. Обновить dotfiles обычным безопасным порядком. Перед checkout на существующей
   машине проверить `home status`; конфликты разбирать вручную, без `reset --hard`.
2. Установить клиенты Codex, Claude Code и OpenCode штатным способом для ОС.
   Убедиться, что `python3`, `git`, `gh`, `node`, `npx` находятся в PATH.
3. Отдельно установить платформенную сборку `codebase-memory-mcp` и проверить
   её происхождение/версию. Бинарник и базы графов в Git не хранятся; этот
   репозиторий не пытается восстановить неизвестный источник локальной сборки.
4. Установить Chromium/Chrome. На macOS подходит приложение в `/Applications`,
   на Linux — Chromium или Google Chrome в PATH. Нестандартный путь задаётся
   локально через `PLAYWRIGHT_MCP_EXECUTABLE_PATH`.
5. Посмотреть план без изменений:

   ```sh
   setup-ai-env
   ```

6. Скачать серверы и установить навыки (сеть и изменения локальных файлов):

   ```sh
   setup-ai-env --install-servers
   setup-ai-env --install-skills
   setup-ai-env --apply
   ```

   Для одного клиента: добавить `--client codex`, `--client claude` или
   `--client opencode`. Без фильтра выбираются все три.

7. Проверить состояние:

   ```sh
   setup-ai-env --check
   check-config
   ```

Для bootstrap новой машины есть явный флаг `./install/bootstrap.sh --packages --ai`.
Он требует уже доступных клиентов, Node/npx и Python; отсутствие зависимости
останавливает установку и требует продолжить с нужного этапа. Обычный bootstrap
больше не изменяет настройки AI-клиентов автоматически.

`--apply` добавляет недостающие серверы, сохраняет все существующие значения,
не трогает другие MCP, авторизацию, настройки модели и правила клиента.
Каждый изменяемый файл сначала копируется в закрытый каталог
`~/.config-backup/ai/<время>/`; копия может содержать секреты и не публикуется.
Повторное применение одинаковых данных не меняет файл. Обнаруженные различия
шаблонов сохраняются локально и показываются как конфликты; это не успешное
обновление содержимого. JSONC OpenCode и симлинки требуют ручного объединения.
Несколько установщиков одновременно не запускать. При ошибке проверить
частично выполненные этапы и резервные копии; общего автоматического отката нет.

### Переход со старого GitHub MCP

Прежний `@modelcontextprotocol/server-github` заменён официальным
`github/github-mcp-server`. По умолчанию установщик бережно сохраняет даже старую
запись и `--check` сообщает об этом. Для явной миграции известной старой записи:

```sh
setup-ai-env --apply --replace-legacy-github
```

Произвольные пользовательские записи с именем `github` автоматически не заменяются.
`setup-claude-mcp` теперь только совместимая команда для
`setup-ai-env --apply --client claude`; старые дополнительные MCP она не возвращает.

## Авторизация остаётся на каждом компьютере

- GitHub: `gh auth login --hostname github.com`. Обёртка `github-mcp-gh` получает
  токен через `gh auth token` и передаёт серверу только через окружение процесса.
  Она не пишет токен в конфиги и не печатает его. Для текущего работающего входа
  новый PAT не обязателен. Права MCP определяются правами этой авторизации `gh`;
  отдельный токен/аккаунт нужен, если требуется более узкий доступ.
- ChatGPT Plus: в OpenCode `/connect` → OpenAI → Sign in with ChatGPT.
- OpenRouter: отдельный вход/API-ключ через `/connect`; Review оплачивается
  из OpenRouter, а не из подписки ChatGPT Plus.
- Context7: публичный URL работает без переноса ключа; возможны ограничения
  частоты. Существующий локальный заголовок авторизации сохраняется.
- Claude Code и Codex: пройти их собственную авторизацию локально.

После настройки открыть новые чаты/перезапустить клиенты. Проверять:
`claude mcp get github`, `claude mcp get playwright`, `codex mcp get github`,
`codex mcp get playwright`, OpenCode `/mcps` и список навыков.
`setup-ai-env --check` проверяет файлы и записи, а не реальное соединение,
баланс провайдера или успешную генерацию. На второй машине отдельно проверены
чтение приватного репозитория через GitHub MCP и пустая страница Playwright.
У `opencode mcp list` наблюдался пустой список при подключённых серверах;
проверка `/mcps`/API дала connected. После установки Matt-навыков их обнаружение
работающим OpenCode осталось неподтверждённым; наличие файлов не считать
доказательством загрузки. Проверить в новом чате на каждой машине.

## Навыки без дубликатов и потери своих файлов

Matt Pocock устанавливается плагином в Codex/Claude. Для OpenCode установщик
копирует только 27 основных навыков из закреплённого commit в
`~/.config/opencode/skills`; экспериментальные папки исключены. Уже изменённые
локальные навыки не перезаписываются. Установка не запускает навыки и не
создаёт issues, метки, PR или коммиты.

Локальные `codebase-memory`, `context7-mcp`, `dotfiles` хранятся как исходные
инструкции в `.config/dotfiles-ai/skills` и добавляются в `~/.agents/skills`.
Существующие отличающиеся файлы сохраняются. Omarchy-навыки `omarchy`,
`omarchy-app`, `diagnose-crash` принадлежат Omarchy и восстанавливаются её
пакетом только на Linux; их системные копии на macOS не переносятся.
Встроенные и подключаемые навыки Codex/документов/браузера устанавливает сам
клиент или его менеджер плагинов, а не этот dotfiles-репозиторий.

Первый универсальный установщик Matt-навыков также создал копии в
`~/.agents/skills`. Их наличие может давать Codex/Claude одновременно плагин и
общие навыки. Этот установщик не удаляет эти файлы автоматически. При очистке
сначала создать резервную копию, проверить владельца и содержимое каждого
каталога и только потом убрать лишний источник. Не ставить один пакет двумя
способами в одном клиенте. Для OpenCode отдельный каталог имеет приоритет.

Перед инженерными навыками выполнить настройку выбранного проекта через
`setup-matt-pocock-skills`: определить трекер и существующие документы.
Не создавать эту настройку сразу во всех репозиториях. GitHub-зеркало проекта
не означает, что задачи нужно публиковать туда.

## Модели, правила и OpenCode

Начальные модели в манифесте: Plan — `openai/gpt-6.1-sol`, Build —
`openai/gpt-6.1-terra`, Review — `openrouter/anthropic/claude-sonnet-5.5`.
Проверить их доступность через `/models` на каждой машине. Старые сессии могут
сохранять свою выбранную модель. Шаблон `review` допускает чтение и поиск;
изменения файлов, shell, другие агенты и сетевые MCP запрещены по умолчанию.
Основной агент передаёт ему diff и результаты проверок. Сам навык `code-review`
не гарантирует независимую модель.

OpenCode V2 использует `mcp.servers`, `disabled`, `agents` и списки `permissions`.
Существующие V1-агенты Codebase Memory пока сохраняются как совместимые шаблоны;
их effective permissions проверяются в установленном клиенте. Плагин
`cbm-augment.ts` со старым абсолютным Linux-путём не распространяется.
Подключённые MCP не дают Review доступ к ним автоматически.

Общий workflow лежит в `~/ghq/AGENTS.md`, входная ссылка Claude —
`~/ghq/CLAUDE.md`. На нестандартном корне проектов разместить эти правила там.
Проверить, что конкретный клиент загрузил родительские инструкции; если он
останавливается на границе репозитория, добавить явную ссылку в проектные
инструкции. Особое правило для всех копий `pvs-efs-assist`: полная проверка
только в закрытом сегменте. Оно остаётся в самом проекте и общем workflow.

Отдельный приватный `frankie-MA/opencode-config` содержит рассмотренный снимок
OpenCode и `sync.py`. Это дополнительный канал сравнения и ручного объединения,
не автоматическая синхронизация живого каталога и не источник авторизации.
После дальнейших правок снимок может отставать. Перед переносом сравнить версии,
проверить секреты и сохранить обе конфигурации. Не запускать одновременно его
применение и `setup-ai-env`.

## Что никогда не переносить через публичный Git

Рабочие `.claude.json`, `.claude/`, `.codex/`, `.config/opencode/`, OAuth,
API-ключи, `auth.json`, `service.json`, личные браузерные профили, кэш, логи,
сессии, `node_modules`, скачанные бинарники, графы/индексы, резервные копии.
Игнорирование не удаляет уже отслеживаемые файлы: `opencode.json` снят с учёта
отдельно, локальный файл сохранён. История Git остаётся; при обнаружении
ранее опубликованного секрета его нужно отозвать, а не просто удалить файл.
Содержимое реальных конфигов не копировать в документацию или диагностический вывод.

## Обновление

Обновлять версии в манифесте осознанно после просмотра upstream и проверки.
Проверка SHA256 GitHub-релиза защищает от повреждения загрузки, но файл сумм
скачивается с того же официального источника и не является независимой подписью.
OpenCode-копии навыков обновлять с ручным сравнением при конфликте; версии
плагинов Codex/Claude проверять отдельно. После обновления: `setup-ai-env --check`,
проверка реальных подключений и нужных навыков, затем `check-config`.
`sync-config` запускается только после проверки и коммита целевых изменений:
он делает push, а грязные посторонние изменения блокируют его.

Источники: [GitHub MCP](https://github.com/github/github-mcp-server),
[Playwright MCP](https://github.com/microsoft/playwright-mcp),
[Matt Pocock skills](https://github.com/mattpocock/skills),
[OpenCode MCP](https://opencode.ai/docs/mcp-servers/),
[OpenCode skills](https://opencode.ai/docs/skills/).

`config-doctor --ai` добавляет строгую проверку AI-файлов к обычному doctor.
Без флага базовый doctor не требует AI-клиентов на машине с одними dotfiles.
Обе команды doctor сначала проверяют чистоту Git; при посторонних правках
проверяй AI отдельно через `setup-ai-env --check`.

## Агенты и глобальные инструкции

В безопасных шаблонах сохранены три агента Codebase Memory (Scout, Verify,
Auditor) для Codex, Claude Code и OpenCode. Команда сервера в шаблонах Codex
использует PATH вместо Linux-пути. Также сохранены глобальные инструкции
Codex (граф и Context7) и OpenCode. `--apply` создаёт только отсутствующие
файлы; существующие инструкции и роли не перезаписываются. После переноса
проверить загрузку ролей и их реальные права в версии клиента. В Claude
роль включает навык `codebase-memory`; он должен быть доступен локально.
Пользовательских файлов команд Claude/OpenCode на момент инвентаризации нет.
